# Alerting on AWS account activity with CloudTrail and CloudWatch

- **Date:** 2026-11-24
- **Topic:** Cloud Security
- **Source:** AWS Academy Learner Lab (Cloud Security), "CloudTrail and CloudWatch"
- **Time spent:** 75 min

## What I learned

- CloudTrail logs every API call in the account. Event history only keeps 90 days for one Region. A trail keeps logs longer and can send them to CloudWatch Logs.
- An EventBridge rule can match a specific API call, like a security group change, and send an alert to an SNS topic that emails me.
- A CloudWatch metric filter can count matching log lines, like failed console logins. An alarm can then fire when the count passes a limit.

## Commands, queries or snippets

```bash
EventBridge rule: match CloudTrail events for security group ingress changes, send to SNS
Metric filter: count ConsoleLogin events that failed
Alarm: fires at 3 or more failures in 5 minutes, notifies SNS
Logs Insights: filter failed logins, count them by source IP and user
```

## Why it matters for security

Opening SSH to the internet and brute-forcing console logins are common attacker moves, and both show up in CloudTrail. Alerts catch them early. Attackers often try to stop the trail, so that's worth alerting on too.

## Questions / next step

- Add alerts for CloudTrail being stopped or deleted, and for root account logins.
