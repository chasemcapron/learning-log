## What I learned

**Logging and Monitoring in AWS**

**AWS Cloud Security Foundations**
- Logging = Making a note of what is happening in your system at any given time. (Who is making transactions, making things, diabling things)
- Monitoring = Reviewing logs to see if anything occurring is out of the ordinary.

**Shared Responsibility Model**
- Customer is responsible for logging and monitoring

**Why is logging important?**
- Logging provides a record of events which is useful for: Troubleshooting, auditing, recordkeeping, incident response and remediation
- Logs are a requirement for demonstrating compliance with regulations, such as: HIPPA, GDPR, LGPD

**What is monitoring?**
- Monitoring is the continuous verification of the security and performance of your resources, applications, and data.
- AWS provides several services that give you the visibility to spot issues before they impact operations (AWS CloudTrail, Amazon CloudWatch, Amazon EventBridge, AWS X-Ray)

**AWS CloudTrail**
- Assists you to enable governance and compliance, as well as operational risk auditing of your AWS account.
- Records actions taken by a user, role, or AWS service as events
- Provides visibility of events in the CloudTrail console.
- Can be used to view, search, archive, or analyze.

**API Security-Relevant Information**
[Name of the API, Identity of the Caller, Time of the API Call, Originating Location of Request, Request Parameters, Response Elements] -> CloudTrail

**Services with built-in logs:**
**Amazon S3**
- Amazon S3 provides detailed access request record through Amazon S3 server access logging
- Server access logs provide useful information for security and access audits
- Server access logs can provide insight into your customer base and assist you to understand your Amazon S3 bill

**Amazon VPC**
- With VPC Flow Logs, you can capture ifnormation about inbound and outbound IP traffic from: VPC, Subnets, individual network interfaces
- Publish flow log data to CloudWatch or Amazon S3

**Elastic Load Balancing**
- ELB access logs capture detailed information about requests sent to your load balancer

**-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------**

**Amazon CloudWatch**
- Is monitoring and observability service
- Provides a unified view of the operational health of your AWS resources, applications, and services

**AWS Cloud Trail**
- Continuously monitors and logs user activities
- Useful for compliance auditing, security, analysis, and troubleshooting
- Helps you determine WHO performed WHAT unauthorized action and WHEN they did it

**Amazon CloudWatch**
- Continuously monitors resource and application performance
- Useful for detecting anomalous service behavior, setting alarms, and discovering insights
- Alerts you that an issue has occurred due to an unauthorized action

**Best practices of logging and monitoring**
- Define your organizational requirements for logs, alerts, and metrics
- Configure service and application logging throughout your workload
- Analyze your logs centerally

## Why it matters for security

It is important for users to understand what AWS resources are available for logging and monitoring. 
Logging any activity on your system good or bad is vital for monitoring efforts. 
When monitoring, analysts are able to detect improper actions, when they occurred, by whom, and how.
